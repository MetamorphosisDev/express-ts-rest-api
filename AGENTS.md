# express-js-tutor-m

Small Express 5 + TypeScript tutorial API backed by Drizzle ORM over Neon Postgres.

## Commands

- `npm run dev` — nodemon + ts-node on `src/index.ts`, serves `http://localhost:8000`. This is the only runnable script; there are no build, test, lint, or typecheck scripts.
- Typecheck the whole project: `npx tsc --noEmit --rootDir .` — plain `tsc --noEmit` FAILS with `TS6059` because `drizzle.config.ts` sits outside `rootDir: ./src`. Don't "fix" this by deleting the config; use the `--rootDir .` override.

## Dependencies gotcha (critical)

`package.json` only declares `express` plus dev tooling. The code also imports **`drizzle-orm`, `@neondatabase/serverless`, `dotenv`** (`src/config/db.ts`) and `drizzle.config.ts` imports **`drizzle-kit`** — none are declared. They exist in `node_modules` only because it was populated once manually. Do **not** run `npm install`, `npm prune`, or delete `node_modules`; a clean install will break the DB code until these deps are added to `package.json`.

There is also a stray duplicate install at `src/node_modules` (an `npm install` was once run inside `src/`). Node resolves it first for files under `src/`, so express/ts-node/typescript are actually loaded from there at runtime. Don't delete it or reinstall inside `src/`; keep installs at the project root.

## Architecture

- Entry: `src/index.ts` mounts routers under `/api/`. New feature = add a `src/routes/<name>/<name>.routes.ts` + `src/controller/<name>/<name>.controller.ts`, then mount it in `index.ts`.
- DB layer: `src/config/db.ts` (drizzle + `@neondatabase/serverless` over HTTP), schema in `src/config/schema.ts` re-exporting `src/config/schema/{role,gallery}`. Requires `DATABASE_URL` in `.env`.
- Migrations: `drizzle/` (generated by drizzle-kit). `drizzle.config.ts` points at `schema: ./src/config/schema.ts`, dialect `postgresql`; `out` is commented out so it uses the default `./drizzle`. Since the DB is remote Neon, `npx drizzle-kit push` applies schema changes directly to the live DB.
- Express 5 (`express@^5.2.1`): behavior differs from Express 4 in places (path-to-regexp syntax, removed/renamed APIs). Prefer checking the installed `node_modules/express` types over 4.x docs.
